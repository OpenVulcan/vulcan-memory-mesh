# 检索与记忆衰减升级分析计划

## 任务目标

- 评估当前项目是否适合引入以下能力：
  - 混合检索（向量 + BM25）
  - RRF 融合与重排序
  - Weibull 记忆衰减模型
- 基于当前真实代码结构，给出细化到数据表、接口、配置与流程的具体改造建议。
- 明确哪些改动属于低风险增量演进，哪些改动属于需要谨慎确认的架构级变更。

## 执行步骤

1. 复查当前 Memory 检索链路、向量接口、关系存储接口与排序逻辑。
2. 复查当前记忆生命周期字段、召回/采纳计数与过期判定逻辑。
3. 评估混合检索、RRF、重排序、Weibull 衰减与现有实现的契合度与阻力点。
4. 设计推荐落地方案，细化到：
   - 新增/修改的数据表与字段
   - 需要调整的接口与返回结构
   - 检索流程和写入流程的改造点
   - 配置项与兼容策略
5. 输出分析文档，并在完成后对照本计划做自检。

## 技术分析原则

- 以当前本地 OSS 运行时为准，不把未装配能力当成既有前提。
- 优先选择最有利于稳定性、可维护性、可回滚性的演进式方案。
- 尽量保持当前依赖方向：`adapters -> app -> logic/domain`。
- 不默认引入新的重型外部基础设施，优先复用现有 `SQLite/LanceDB/gRPC` 组合。

## 验收标准

- 给出是否建议引入三类能力的明确结论。
- 给出至少一套“推荐实施方案”和一套“最小改动方案”。
- 说明每一项改动对应的代码位置、表结构调整建议和接口影响面。
- 明确兼容性风险、迁移成本与实施顺序建议。

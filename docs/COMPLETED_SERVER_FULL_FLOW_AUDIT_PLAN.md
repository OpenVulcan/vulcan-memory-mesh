# 服务端完整流程审计计划 / Server Full Flow Audit Plan

## 1. 任务目标 / Task Goal

- 系统性梳理当前服务端的完整处理链路，包括启动装配、gRPC 入站、请求校验、文本清洗、标准化、长期记忆判定、存储与返回路径。
- 盘点项目中与服务端相关的核心数据结构、字段作用、gRPC 对外接口、请求/响应参数、配置入口、规则加载机制以及提示词来源。
- 产出一份可直接供研发/测试/集成使用的项目级说明，确保“接口层 -> 应用层 -> 逻辑层 -> 配置/规则层”的信息闭环。

## 2. 执行步骤 / Execution Steps

1. 扫描仓库目录与服务端入口，定位运行时启动点、依赖装配位置和 gRPC 服务注册位置。
2. 梳理 gRPC proto、服务实现以及 DTO/领域模型之间的映射关系，整理所有开放接口、请求字段、响应字段和语义。
3. 追踪核心调用链，覆盖文本净化、PII 规则、Noise Gate、post-action、记忆写入与查询等关键流程。
4. 盘点配置结构、规则目录、提示词目录与加载优先级，明确系统配置与用户覆盖的生效方式。
5. 汇总为文档，逐项对照计划核验覆盖度；若发现遗漏，补充分析直到闭环。

## 3. 技术方法 / Technical Approach

- 以源码静态审查为主，结合构建脚本、配置文件、proto 定义和现有文档交叉验证。
- 优先遵循仓库既有依赖方向：`adapters -> app -> logic/domain`。
- 输出时区分“当前已实现行为”与“文档声明行为”，避免把历史文档误当成当前运行事实。

## 4. 验收标准 / Acceptance Criteria

- 明确服务端启动入口、依赖装配关系和完整处理流程。
- 明确所有 gRPC 开放接口、请求参数、返回参数、关键错误/状态语义。
- 明确核心数据结构及字段作用，至少覆盖入参、标准化结果、存储相关模型与配置结构。
- 明确提示词、PII 规则、Noise 规则等资源的目录、加载方式和优先级。
- 形成最终说明，并将本计划文件在完成后重命名为 `COMPLETED_` 前缀。

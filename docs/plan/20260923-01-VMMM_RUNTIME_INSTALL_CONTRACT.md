# VMMM 安装器所需 VMM 运行时与发行契约

状态：实施中。

## 任务目标

为独立 VMMM 安装器提供可验证、可配置、可回滚的 VMM 正式包契约。保留旧配置的运行行为，避免把仓库开发配置、测试凭据或不完整的存储依赖带入发行包。

## 执行步骤

1. 对照现有配置加载、存储、服务和发行代码确认权威字段及目录布局。
2. 在 split/controller 模式增加显式本地数据根字段，空值沿用旧路径；阻止模式切换时静默迁移旧数据库。
3. 增加配置 schema、完整配置与规则资产校验、健康探测命令，供管理器在安装前与运行后调用。
4. 让服务注册携带显式配置根，并支持重启、自启启停和状态查询。
5. 将每平台发行包改为同时包含 native、split、controller 所需运行依赖，严格列举可打包配置文件，排除开发覆盖配置。
6. 使用独立于 Windows Certum 代码签名的 Ed25519 清单签名；私钥仅存 GitHub Actions Secrets，固定公钥随仓库提交；缺密钥或验签失败时不发布。
7. 同步 README 与发行指南，验证测试、标准构建和目标平台产物。

## 技术选型

- 保持现有 Go 配置模型、YAML 配置链和 VMM CLI 为最终权威。
- 外部发行清单采用 Ed25519 分离签名，签名实现使用标准库；Certum 代码签名待证书签发后接入。
- 每个平台一个完整包，包内收据声明实际文件摘要和存储能力。
- 继续使用现有服务管理和打包脚本，仅扩充明确协议。

## 验收标准

- 旧 split/controller 配置仍使用旧数据库路径，新字段在对应模式生效且路径冲突安全拒绝。
- schema 与 validate 反映真实配置字段；校验失败不回显凭据。
- 服务模式和命令行模式读取同一显式配置根，健康探测使用现有 gRPC 契约。
- 五个平台的包都包含三类本地依赖，且不包含开发用 `configs/config.yaml`。
- 正式清单按固定公钥验证；缺失 Secret 或摘要不符失败关闭。
- 聚焦测试、`go test ./...`、标准构建和发行包测试通过；跨平台交叉编译与原生运行证据分别记录。

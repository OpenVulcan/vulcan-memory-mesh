# LLM Key 容灾实现自检计划

## 任务目标

对当前已落地的 LLM / Embedding / Rerank Key 级容灾实现进行一次完整自检，重点确认配置兼容性、运行时行为、错误分类、轮询策略与测试覆盖是否存在逻辑漏洞、回归风险或与设计不一致的问题，并形成审查结论。

## 执行步骤

1. 审阅配置层实现，确认 `api_key` 与 `api_keys` 的兼容、归一化、环境变量覆盖和校验逻辑是否闭环。
2. 审阅应用装配层实现，确认 `llm`、`embedding`、`rerank` 的 failover 包装方式、固定模型约束和 key 池回退逻辑是否符合设计。
3. 审阅 `ai_key_failover` 运行时实现，重点检查失败分类、冷却时间、轮询策略、重试顺序和边界条件。
4. 审阅新增测试与相关已有测试，评估关键路径是否覆盖，并通过执行测试验证当前代码状态。
5. 输出审查结论；若发现问题，按严重程度给出带文件定位的 findings，并说明影响范围与建议修复方向。

## 技术选型与审查原则

- 以仓库当前代码为准，不凭设计文档主观假设实现正确性。
- 以“正确性优先于便利性”为原则，优先识别可能导致错误结果、静默退化或配置歧义的问题。
- 结合单元测试与静态代码阅读共同判断，不仅看是否能通过测试，还要看行为是否稳定可解释。
- 对于容灾逻辑，优先关注“是否会错误切 key”、“是否会错误停 key”、“是否会在所有 key 都不可用时给出误导性结果”。

## 验收标准

- 明确说明当前实现是否存在可复现或高风险问题。
- 每个问题都给出具体文件定位、触发条件和影响描述。
- 若未发现明确问题，也要说明剩余风险点与测试盲区。
- 审查过程完成后，在文档末尾补充执行变更总结，并将计划迁移到 `docs/completed/`。

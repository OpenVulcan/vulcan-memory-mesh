# 任务计划：配置环境变量覆盖收敛

## 一、任务目标

修复当前配置加载链路中“即使配置文件未显式使用环境变量占位符，也会被 `.env` / 进程环境变量覆盖”的行为，使运行时只在配置文件明确声明 `${ENV_NAME}` 依赖时才读取并应用对应环境变量值。

## 二、技术方案

### 2.1 现状梳理

确认配置加载流程中：

1. `.env` 文件是如何被自动预加载到进程环境中的。
2. `applyEnvOverrides` 是如何无条件把支持的环境变量覆盖到配置对象上的。
3. 现有测试和文档是否默认依赖这种“全局环境变量优先”的旧行为。

### 2.2 覆盖策略收敛

将环境变量参与配置解析的条件收敛为：

1. 只有配置层正文中显式出现 `${ENV_NAME}` 占位符时，才允许读取该环境变量。
2. 不再对未引用环境变量的配置字段做无条件环境覆盖。
3. 继续保留 `.env` 与进程环境对占位符展开的支持，避免破坏现有的显式环境注入链路。

### 2.3 测试与文档同步

补充或更新配置测试，验证：

1. 未使用 `${ENV}` 的 YAML 值不会再被环境变量静默覆盖。
2. 使用 `${ENV}` 的 YAML 值仍然可以通过 `.env` / 进程环境正常注入。
3. 如有必要，同步更新与配置覆盖规则直接相关的说明文档。

## 三、执行步骤

1. 阅读配置加载、`.env` 预加载与环境覆盖相关代码及现有测试。
2. 实现“仅显式引用环境变量时才生效”的加载规则。
3. 补充 / 更新回归测试。
4. 运行配置相关测试与全量测试验证无回归。

## 四、验收标准

1. 纯字面量 YAML 配置不会再被 `.env` 或进程环境变量无条件覆盖。
2. 显式使用 `${ENV}` 的配置项仍能正常读取环境变量。
3. 配置加载相关测试通过，且全量测试无回归。

## 执行变更总结

### 1. 核心修复与调整概述

本次修复将配置加载中的环境变量参与条件从“默认全局覆盖”收敛为“显式占位符驱动”：

1. 先扫描原始配置层里的真实值，收集实际出现的 `${ENV_NAME}` 引用。
2. `.env` 只为这些被显式引用的键补充值，不再把无关变量整体灌入运行时。
3. `applyEnvOverrides` 与已移除 AI 环境变量校验都改成按引用白名单生效，避免字面量 YAML 被旧 `.env` 静默覆盖。
4. 同步更新文档，把“环境变量是独立覆盖层”的表述改成“只有显式占位符时才参与展开”。

# 任务目标

根据最新确认的提示词包设计约束，校正启动期提示词校验逻辑，确保运行时只依据当前配置选择的提示词包进行判定，不再额外强制某个固定提示词目录；同时保留“提示词包必须完整”的约束，不回退历史兼容逻辑。

# 执行步骤

1. 复核当前 `prompt_language` 的配置归一化、启动校验和运行时读取链路，确认哪些位置仍存在与设计不一致的“固定目录强制校验”。
2. 修改提示词管理器初始化逻辑，使启动期仅校验当前配置归一后的目标提示词包。
3. 保持现有“用户提示词包一旦存在就必须完整”的校验策略，不恢复旧的部分覆盖或历史目录兼容行为。
4. 更新并补充相关测试，覆盖以下场景：
   - 选择自定义提示词包时，不再要求 `default_en` 必须存在；
   - 当前选中的提示词包缺失时仍然快速失败；
   - 用户提示词包不完整时仍然快速失败。
5. 运行与本次修改直接相关的测试，确认配置与提示词管理链路行为稳定。

# 技术选型

1. 延续当前 `internal/config/prompt_bundle.go` 中的提示词包归一化规则，不新增历史兼容分支。
2. 在 `internal/config/manager.go` 中收敛启动校验入口，避免把“运行时默认值”误实现成“打包时强制依赖”。
3. 通过现有 `manager_test.go` 与 `config_test.go` 补测试，不引入新的测试框架。

# 验收标准

1. 当配置选择 `default_en`、`default_cn` 或自定义提示词包时，启动仅校验当前选中的提示词包完整性。
2. 不再因为未打包 `default_en` 而阻断一个已显式选择其他提示词包的运行时启动。
3. 用户提示词包仍保持“存在即必须完整”的严格约束。
4. 相关 Go 测试通过，且没有引入新的提示词路由回退逻辑。

# 执行变更总结

## 1. 核心修复与调整概述

本次已按最新设计约束收敛启动期提示词校验逻辑：取消了在配置加载前和提示词管理器初始化阶段对 `default_en` 的固定强制依赖，改为只围绕当前配置归一后的目标提示词包进行校验。同时保留现有严格约束，不恢复“用户提示词包可部分覆盖”或“历史目录兼容”行为。

## 2. 📂文件变更清单

- 修改：`internal/config/loader.go`
- 修改：`internal/config/manager.go`
- 修改：`internal/config/loader_test.go`
- 修改：`internal/config/manager_test.go`

## 3. 💻关键代码调整详情

- 在 `internal/config/loader.go` 中将系统配置根目录判定从“必须存在 `prompts/default_en`”调整为“必须存在系统基础配置文件 `base.yaml`”，避免在配置尚未加载时就预先绑定某个固定提示词包。
- 在 `internal/config/manager.go` 中删除 `NewPromptManager` 对 `default_en` 的预校验，改为仅校验 `prompt_language` 归一化后的当前生效提示词包。
- 在 `internal/config/manager_test.go` 中新增“仅打包自定义提示词包也可启动”的测试，并保留“当前选中提示词包必须完整”的失败断言。
- 在 `internal/config/loader_test.go` 中新增布局解析测试，验证打包目录在不包含 `default_en` 时仍能被识别为合法系统配置根。

## 4. ⚠️遗留问题与注意事项

- 当前运行时默认值仍然是 `default_en`；如果配置未显式切换，系统依旧会在提示词管理器初始化阶段要求 `default_en` 完整存在，这属于当前设计下的预期行为。
- 本次没有恢复旧 `prompts/default` 目录兼容，也没有放宽用户提示词包完整性要求；后续若设计改变，需要单独补充迁移策略和测试。

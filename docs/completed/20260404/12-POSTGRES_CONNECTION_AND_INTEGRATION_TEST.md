# PostgreSQL 组合库连接与实际链路验证计划

## 任务目标

验证当前本地配置中的 PostgreSQL 组合库连接是否可用，并执行至少一条真实链路测试，确认配置、连接、运行时装配与基础命令行为一致。

## 执行步骤

1. 检查 `configs/local.json`、`.env` 以及运行时配置覆盖链路，确认 PostgreSQL 相关配置已经可用于本地测试。
2. 使用不暴露敏感信息的方式验证 PostgreSQL 连接是否可建立，并确认当前数据库具备运行所需的基础条件。
3. 基于当前 CLI 能力执行至少一条实际组合库链路命令，优先验证：
   - 启动前配置可被正确解析；
   - PostgreSQL 连接建立成功；
   - 组合库存储相关命令可实际执行。
4. 如果测试失败，定位失败点是配置问题、数据库问题还是代码问题，并给出可复现结论。
5. 将测试过程、结果、发现的问题与后续建议回填到本计划文档。

## 技术选型与策略

- 优先复用仓库现有标准运行入口与调试命令，不额外编写临时脚本破坏当前工程结构。
- 严格避免在终端输出、文档或最终回复中泄露完整 DSN、用户名密码等敏感信息。
- 若数据库已由用户配置完成，则优先做真实连接与真实命令验证，而不是只做静态配置检查。

## 验收标准

- 可以确认当前本地 PostgreSQL 配置是否已被运行时正确读取。
- 至少完成一次真实数据库连接验证。
- 至少完成一次真实组合库相关命令验证，并明确成功或失败结果。
- 若存在失败，能够提供清晰的失败阶段与原因说明。

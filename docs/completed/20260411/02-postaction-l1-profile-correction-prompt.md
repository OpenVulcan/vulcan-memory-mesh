# 任务计划：调整 postaction L1 提示词对用户显式画像纠正的提炼规则

## 任务目标

修正 `postaction_l1_main` 的提示词约束，使其在用户明确声明、补充或纠正自身画像信息时，不再仅把助手响应理解为“回答了纠正”，而是要求从该轮中提炼出可供后续画像评审链路使用的 `profile_nodes` 候选，交由后续 LLM 和 VMM 画像替换流程继续判断是否接纳、替换或退役旧画像。

## 详细执行步骤

1. 定位当前 `postaction_l1_main` 对画像回显、画像复述、用户显式确认/补充/纠正的提示词定义。
2. 梳理现有文档里对 “只有用户自己明确确认、补充、纠正或直接陈述这些偏好时，才允许进入长期画像系统” 的描述，确认与提示词是否存在表述落差。
3. 修改 `postaction_l1_main` 提示词：
   - 明确区分“助手代答/猜测/迎合性总结”与“用户显式纠正画像”。
   - 明确要求当用户显式纠正旧画像时，生成新的画像候选，而不是因为当前轮表面上像一次问答就跳过提炼。
   - 明确这些候选只是提供给后续评审与画像替换流程，不代表 L1 阶段直接完成系统画像更正。
4. 如存在对应中文文档说明缺口，同步更新文档，确保仓库行为说明与提示词保持一致。
5. 运行最小必要验证，确认提示词资源和文档修改未破坏测试与仓库约束。

## 技术选型与处理原则

- 采用最小影响面修改，优先调整 prompt bundle 中 `postaction_l1_main` 的规则描述，不轻易扩大到运行时代码。
- 保持现有 `postaction L1 -> postaction L2 -> 画像接纳/替换` 职责边界：
  - L1 负责提炼候选；
  - 后续评审链路负责是否真正替换系统画像。
- 若文档已有相同原则但不够明确，则补充“纠正场景”的边界说明，避免后续提示词和文档再次漂移。

## 验收标准

- `postaction_l1_main` 提示词明确覆盖“用户显式纠正画像”场景。
- 提示词明确说明：此类场景应输出画像候选，而不是仅因助手返回了纠正内容就视作系统已纠正或直接跳过。
- 提示词明确说明：最终是否替换 VMM 画像，应交由后续画像评审链路决定。
- 如有文档更新，文档表述与提示词要求一致。
- 相关最小测试或校验命令执行通过；若无法执行，需在总结中明确说明原因。

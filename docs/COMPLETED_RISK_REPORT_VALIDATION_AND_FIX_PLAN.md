# RISK REPORT VALIDATION AND FIX PLAN

## 任务目标

- 逐条核查用户提供的风险报告内容，确认每个问题是否真实存在，避免因为对代码路径理解不完整而误修。
- 仅对确认真实存在且确有必要修复的问题实施修改，并补充验证。
- 将每条问题的核查结论、是否需要修复、实际修复结果统一写入一份中文报告。

## 执行步骤

1. 核对当前工作区状态，避免中断残留影响本次判断。
2. 逐条审阅报告中的 8 个风险点，对照实际代码、运行路径和现有测试判断：
   - 是否真实存在
   - 是否属于误报/设计取舍/非问题
   - 若存在，影响范围和修复必要性
3. 只对确认真实存在的问题做最小化修复，并补充对应测试或验证。
4. 运行仓库要求的测试与构建命令。
5. 生成风险核查与修复报告，并将计划文件重命名为 `COMPLETED_` 前缀。

## 技术约束

- 不因为初步分析报告就直接改代码，必须先验证。
- 不修改外部 gRPC 契约，除非验证后发现对外协议确有真实缺陷且必须调整；若遇到此类情况需暂停说明。
- 新增代码、测试和文档继续遵守仓库双语注释规范。

## 验收标准

- 报告中的每个问题都有明确结论：存在 / 不存在 / 不需要修复。
- 只有真实存在的问题被修复，且修复有对应验证。
- 产出一份记录完整结论和处理结果的中文报告。
- 通过以下验证：
  - `go test ./internal/adapters/inbound/grpcapi ./internal/app/usecase ./internal/logic/processor ./internal/platform/textutil ./internal/platform/pii ./internal/config -count=1`
  - `go test ./... -count=1`
  - `.\make.ps1 build`
